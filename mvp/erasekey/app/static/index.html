Cryptographic deletion, tested against time travel

What happens when an old backup brings a deleted key back?

Run the experiment locally. EraseKey encrypts a sample record, destroys its subject key, restores stale key state, then uses a signed receipt to erase it again.

Uses generated sample data and the mock KMS. Do not expose this demo server to the public internet.

What this proves

A deletion decision can survive a stale application restore.

The receipt journal is deliberately outside SQLite. On application startup, EraseKey verifies it and reapplies completed erasures before serving traffic.

This is an engineering demonstration, not a compliance product or a distributed transaction. Real deployments need independent, immutable receipt storage and managed signing keys.

EraseKey is a small engineering experiment.
